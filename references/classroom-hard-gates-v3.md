# Classroom Hard Gates v3 — 授業PPTXの納品拒否条件

このファイルは Classroom Mode の**最上位の品質ゲート**である。

目的は「それっぽいPPTX」を作ることではない。
**教室後方から読め、授業の説明順に使え、最終レンダリングで崩れていないPPTXだけを完成版とする。**

## 1. 文字サイズは下限ではなく役割で決める

完成版の基準：

| 要素 | Hard Gate |
|---|---:|
| 表紙タイトル | **54pt以上** |
| 通常タイトル | **38pt以上** |
| 日本語本文 | **24pt以上** |
| 短いタグ・文法ラベル | **22pt以上** |
| 生徒が読むクリック案内 | **22pt以上** |
| 英語の説明文・例文 | **28pt以上** |
| 主役の英文 | **36pt前後以上を優先** |
| 出典・ページ番号 | 例外 |

禁止：

- 15–19ptの表・解説・理由・ヒント
- 「情報が多いから」と本文を20pt前後に落とす
- 28ptのタイトルを授業用タイトルとして納品する
- 小さい表に大量の情報を詰める

入らないときは：

1. 文を短くする
2. 説明をノートへ移す
3. ボックスを広げる
4. レイアウトを変える
5. クリック表示に分ける
6. スライドを増やす

**フォント縮小は解決策にしない。**

---

## 2. タイトルは最終レンダリングで判定する

タイトルはPPTX上のボックス内に収まっていても、レンダラーで自動改行し得る。

FAIL：

- 最終行が1–6文字程度だけ残る
- 日本語の単語・意味のかたまりを途中で割る
- タイトルが本文に重なる
- 2行タイトル用の高さがない
- タイトルが38pt未満
- 表紙タイトルが54pt未満

修正は「意味の切れ目で明示改行」またはタイトル短文化で行う。

---

## 3. スピーカーノートは授業教材の一部

画面に載せない詳しい説明はノートへ移すため、Classroom Modeでは原則：

- 表紙以外の**全内容スライドに substantive speaker notes を入れる**。
- ノートには少なくとも、説明ポイント・生徒への問い・想定回答・クリック順のいずれかを含める。
- 画面を小さな文字で詳しくする代わりにノートへ逃がす。

ユーザーが明示的に「ノート不要」と言った場合のみ例外。

---

## 4. クリック式はデフォルト

Classroom Modeは原則 presenter-controlled。

- 各内容スライドに on-click の段階表示を入れる。
- 問題スライドは、問題 → ヒント/選択肢 → 正解 → 理由。
- 自動送り禁止。
- 答えの初期表示禁止。
- 1枚2–6クリックを目安。
- デッキ全体で clickEffect が0なら完成版にしない。

ユーザーが明示的に「アニメーション不要」「静的で」と言った場合のみ例外。

---

## 5. レイアウト崩れは1件でもHard FAIL

FAIL例：

- タイトルと英文が重なる
- 英文同士が重なる
- ボックス外へ文字が出る
- 文字の上下が切れる
- 2行の内容を1行用の高さへ入れる
- 不自然な自動改行
- 文字化け
- 画像の縦横比崩れ
- 小さい表が読めない

**XMLが正常でも、PNGで崩れていればFAIL。**

---

## 6. 英語教材では英文が視覚上の主役

英語授業の中心スライドで、英文が周囲の説明文より小さい状態を禁止する。

原則：

1. 英文
2. 注目箇所
3. 判断の手がかり
4. 意味・仕組み
5. 詳細はノート

の順に視覚階層を作る。

---

## 7. 同じカードを並べるだけのAI資料を禁止

次のパターンが3枚以上連続したら再設計する。

- 同サイズの角丸カードを3–6個並べる
- 上にタイトル、下にカード群、の繰り返し
- 全要素が同じ視覚強度
- 色だけ変えて同じ構図
- 表を小さくして情報を詰める

授業の思考に合わせて、比較・巨大英文・Before→After・フロー・クイズ・誤文添削・タイムライン等に構図を変える。

---

## 8. 色は意味を固定する

推奨：

- ブルー = 元文・手がかり
- オレンジ = 今注目する条件
- グリーン = 正解・完成形
- 赤 = NG・注意
- グレー = 補助

同じ色を別の意味で使い回さない。
1枚で多色化しすぎない。

---

## 9. フローチャート指定は専用ルールを適用

`references/classroom-flowchart-rules.md` を読む。

「角丸ボックスを横並びにして線でつなぐ」だけではフローチャート要件を満たさない。

---

## 10. 完成版と呼べる条件

完成版は：

- machine QA FAIL 0
- rendered PNG全ページ確認済み
- visual QA PASS
- 修正後に再レンダリング済み
- delivery gate PASS

のすべてを満たしたものだけ。

どれか未実行なら「未検証」「途中版」であり、完成版とは呼ばない。

---

## 11. 実失敗から追加された拒否条件

2026-09-08「時制② フローチャート式」で確認された失敗：

- 表紙タイトル30pt
- 通常タイトル28pt
- 15–20pt級の本文・表が大量
- clickEffect 0
- speaker notes 0
- タイトルの自動折返しと本文への干渉
- フローチャート指定なのに後半がカード・表中心
- 色の役割がページごとに揺れる

これらは今後「仕上げの好み」ではなく、**納品拒否条件**として扱う。

---

## 12. 2026-09-10追加：レンダリング安定性と英文改行

詳細は `references/classroom-rendering-stability.md` を必ず参照する。

次のどれかがあればHard FAIL：

- 強調色・太字・下線を付ける都合で、1つの英文を不自然な複数段落へ分割している
- `If it` / `rains tomorrow,` のように、本来ひとまとまりの節が不要に割れている
- `If I` / `were you,` のように、主語だけが不自然に孤立している
- 英単語の途中で改行している
- 見出し・英文・和訳を1つの枠へ空行で詰め込み、和訳や本文が枠線へ接触している
- 通常タイトル38pt以上でも、2行を収める高さがなく文字が上端・下端で切れる
- AutoFit・自動縮小に依存し、表示環境によって行数や文字サイズが変わる前提の設計
- 本文・例文・和訳の内部余白がほぼ0で、文字が枠線に接触する
- 修正後の最終PPTXそのものから再レンダリングしていない
- 保存済みPNGに異常が残っているのに「目視OK」と判定している
- LibreOffice等の代替レンダラー確認だけで「Microsoft PowerPoint実機確認済み」と報告する
- XML・静止画の確認だけで「クリック再生確認済み」と報告する

英文の部分強調は、原則として**同一段落内のrun書式**または、英文の位置を変えない強調用図形で行う。

完成報告では、静止画確認とクリック動作確認を別々に記録する。

---

## 13. 2026-09-11追加：文字の周囲に装飾的な四角枠を付けない

Classroom Mode の標準は **borderless text containers** とする。

次の状態はHard FAIL：

- タイトル、本文、英文、和訳、解説、正解、ヒントなどを載せるためだけの矩形に、目立つ外枠線が付いている
- 左右比較の2領域を、色付きの四角い線で大きく囲っている
- 薄い背景色のカードに、さらに外枠線を重ねている
- 同じような「文字＋四角枠」のカードが複数枚にわたり繰り返される
- クイズの選択肢を必要性なくボタン風の四角枠で囲っている

標準の修正方法：

1. テキストボックスの外枠線を `no line` にする
2. 必要なら薄い背景面だけ残す
3. 区切りは余白・見出し位置・短いアクセント線・下線・矢印で作る
4. 枠線そのものに意味がある図解のみ例外とする

例外：表の罫線、座標軸、フローチャートのノード境界、ベン図、実物UI再現など、**境界線そのものが情報を持つ場合**。

ただし例外でも、意味のない外枠は付けない。
