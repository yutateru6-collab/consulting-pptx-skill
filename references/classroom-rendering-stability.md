# Classroom Rendering Stability — PPTXの改行・文字枠・表示環境差を防ぐ

このファイルは、授業用PowerPointで起きやすい **不自然な英文改行、タイトル切れ、文字枠不足、フォント置換、レンダリング差、クリック演出によるレイアウト崩れ** を防ぐための必須ルールである。

対象は Classroom Mode のPPTX制作・修正・QA。`references/classroom-hard-gates-v3.md`、`references/classroom-slide-rules.md`、`references/classroom-visual-qa-v3.md` と併用する。

**生成成功、PPTX保存成功、PDF化成功、機械チェックPASSだけでは完成としない。**

---

## 1. 英文の色分けと改行を分離する

英文は原則 **1文＝1つのテキストボックス** とする。

- 色分け・太字・下線は、同じ段落内の run 単位で設定する。
- 強調語の前後で段落を分けない。
- 色を変えるためだけに英文を複数のテキストボックスへ分割しない。
- 改行は、節・コンマ・意味のまとまりなど教育上自然な位置にだけ入れる。
- 主語だけ、助動詞だけ、冠詞だけなどが1行に孤立する改行を作らない。

### NG

```text
If it
rains tomorrow,
I will stay home.
```

```text
If I
were you,
I would tell the truth.
```

### OK

```text
If it rains tomorrow,
I will stay home.
```

```text
If I were you,
I would tell the truth.
```

長い英文を複数行にすること自体は可。ただし、**意味のまとまりを壊さない意図的な改行**にする。

生成後は英文の文字列だけでなく、**段落数・手動改行位置・空段落の有無**も確認する。

---

## 2. 見出し・英文・和訳を別のテキストボックスにする

次を1つのテキストボックスへ空行で詰め込まない。

- 見出し
- 英文
- 日本語訳
- 解説
- 正解・補足

原則として役割ごとに別のテキストボックスを使う。

理由：1つの枠に複数役割を詰めると、フォント置換や1行増加だけで和訳が枠線へ接触したり、下端が切れたりするため。

**空行・連続スペース・全角スペースで位置調整しない。** 座標、テキスト枠、段落間隔で配置する。

---

## 3. 1行タイトルと2行タイトルは別設計

通常タイトルは38pt以上を維持したうえで、文字量に合う高さを確保する。

- 1行用タイトル枠に2行の文章を押し込まない。
- 2行タイトルになる場合は、タイトル枠を高くし、その分本文の開始位置も下げる。
- 自動折返しで偶然ちょうどよく見えることを前提にしない。
- 2行目が1〜6文字だけになるタイトルはFAIL。
- 文字を縮小して1行へ戻すことを修正策にしない。

タイトル枠が不足する場合の優先順位：

1. 意味を保った短文化
2. 意味の切れ目で明示改行
3. タイトル枠を高くする
4. 本文開始位置を下げる
5. 本文レイアウトを組み替える

---

## 4. テキストボックスの内側余白を確保する

文字が枠線に接触するレイアウトは禁止。

- テキストボックスの上下左右に実用的な内側余白を取る。
- ほぼ0の internal margin を通常の本文・例文・和訳に使わない。
- 見出し、英文、和訳の間は、読み分けられる視覚的間隔を確保する。
- 左右比較では、左右の見出し・英文・和訳の開始位置をそろえる。
- 位置をそろえるために片側だけ文字を小さくしない。

枠内余白が足りない場合、文字サイズを下げるより先に、枠を広げる・高くする・要素を分ける。

---

## 5. AutoFit・自動縮小に依存しない

PowerPointのAutoFitや自動縮小が働くことを前提に設計しない。

- 自動縮小で最低文字サイズを下回る状態を禁止する。
- AutoFitをオフにしただけで修正完了としない。
- 文字サイズ、実際の行数、行間、段落間隔、テキスト枠の高さ、内側余白をセットで確認する。
- 文字が収まらない場合は、枠・配置・情報量を修正する。

**テキストボックス自体がスライド内にあっても、内部の文字が切れていればFAIL。**

---

## 6. フォント指定・利用可否・埋め込みを区別する

フォント名を指定しただけで表示安定性が保証されたと判断しない。

- 日本語フォントと英語フォントを明示する。
- 1デッキ内で不要なフォント混在を避ける。
- 制作環境に存在しても授業PCに存在するとは限らない。
- 使用先のフォント利用可否が未確認なら、その事実を制作記録に残す。
- フォント埋め込みをしていないのに「埋め込み済み」と報告しない。
- フォント変更後は全ページを再レンダリングする。

重要案件では、最終利用環境が Windows + Microsoft PowerPoint なら、その環境での表示確認を最終基準とする。

LibreOffice等の代替レンダラーだけで確認した場合は、**「PowerPoint実機では未確認」**と明記する。

---

## 7. クリック演出のために英文を細切れにしない

クリック式の標準提示は次を優先する。

1. 英文全体を表示
2. クリックで重要箇所の下線・囲み・色強調を表示
3. 次のクリックで和訳・説明を表示
4. 最後に結論・答えを表示

単語を強調するためだけに英文自体を複数段落や複数テキストボックスへ分割しない。

強調用の線、枠、矢印などは編集可能な図形として追加し、**強調表示によって英文そのものの位置や改行が変わらない**構造にする。

アニメーションの対象Shape、開始条件、クリック順、クリック数を確認する。

**アニメーション効果数と、授業で必要なクリック回数を混同しない。**

---

## 8. 生成データ・静止画・クリック動作を別々に検査する

### A. 生成データQA

PPTX内部で確認する：

- 不要な段落・改行・空段落
- 最低文字サイズ違反
- テキストボックス外への配置
- 極端に小さい内部余白
- タイトル枠の高さ不足
- 複数行テキストに対して明らかに低すぎる枠
- フォント混在
- 文字化け
- アニメーション対象Shape ID
- on-click / 自動送り

機械で実測できないものを「検査済み」と扱わない。

### B. 静止画QA

最終版PPTXから全ページをPDF→PNGへレンダリングする。

**コンタクトシートだけでは不可。各スライドを1枚ずつ十分な大きさで確認する。**

特に見る：

- タイトル上端・下端
- 1行/2行タイトルの高さ
- 英文の改行位置
- 主語だけ、助動詞だけ等の孤立行
- 英単語途中の改行
- 和訳の下端
- 枠線と文字の接触
- 左右比較の高さ・開始位置
- 文字同士・文字と図形の重なり
- 不自然な空白
- フォント置換による幅変化

「見た」だけでなく、**英文と和訳を実際に読んで確認する。**

### C. クリック動作QA

次を別の状態として確認する。

- 初期表示
- クリック1
- クリック2
- …
- 全表示

確認項目：

- 答えの先出し
- 表示漏れ
- 重複表示
- 強調図形のずれ
- 自動再生
- クリック順と説明順の不一致

PDFや通常のPNGだけを見て、クリック動作まで確認済みと報告しない。

---

## 9. 最終利用環境で確認できたことだけを報告する

確認結果は最低限、次の4区分で記録する。

- **機械チェック**：実行したchecker名と結果
- **静止画確認**：確認したページ数、修正事項、未解決事項
- **クリック動作**：PowerPoint実再生か、PPTX内部設定確認のみか
- **使用環境**：Microsoft PowerPoint / LibreOffice / その他 / 未確認

禁止表現：

- LibreOfficeレンダリングだけで「PowerPoint表示確認済み」
- XML確認だけで「クリック再生確認済み」
- 一部ページだけ見て「全ページ目視OK」
- 修正前のレンダリングを使って「最終版確認済み」

確認できない事項は未確認と明示する。

---

## 10. 修正後は最終ファイルそのものを再検査する

文字、改行、フォント、枠、配置、アニメーションのどれかを修正したら、必ず：

1. 最終PPTXを保存
2. そのPPTXを再度開く
3. checkerを再実行
4. そのPPTXから再レンダリング
5. 全ページを再確認
6. クリック設定を再確認
7. 最終版だけを納品

途中版・修正前版のQA結果を最終版へ流用しない。

---

## 11. 実失敗から追加されたHard FAIL

2026-09-10「仮定法 6枚 クリック式」で実際に確認された失敗を、今後の拒否条件へ追加する。

### 英文

- 強調語のために英文を段落分割し、不自然な2〜3行になっている
- `If it` / `rains tomorrow,` のように、本来1つの節が不要に分割されている
- `If I` / `were you,` のように、主語と補語が不自然に分断されている

### タイトル

- 38pt以上でも、2行を収める高さがない
- 自動縮小・AutoFit任せで、環境によって行数が変わる
- タイトルが上端で切れる、本文へ侵入する

### 本文枠

- 内側余白がほぼ0で、文字が罫線に接触する
- 和訳の下端が枠線に接触する
- 行数が増えた結果、下のテキストが切れる

### QA

- 保存したPNGに異常が残っているのに「目視OK」と判定する
- 代替レンダラーの結果だけでPowerPoint実機の表示まで保証する
- 静止画だけでクリック動作まで確認済みとする

これらは「好み」ではなく **納品拒否条件** とする。

---

## 12. 完成判定

次のすべてが成立したときだけ完成版とする。

- 一般machine QA PASS
- Classroom Hard Gate QA PASS
- Classroom詳細QA PASS
- 全ページ最終レンダリング確認済み
- 不自然な英文改行 0
- タイトル・英文・和訳の文字切れ 0
- 文字と枠線の不自然な接触 0
- visual QA PASS
- 修正後の最終ファイルから再レンダリング済み
- クリック動作について、確認方法を正確に記録済み

1つでも未確認・FAILなら「完成版」と呼ばない。
